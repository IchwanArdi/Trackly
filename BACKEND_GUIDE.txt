  BAGIAN 1: TECH STACK YANG DIGUNAKAN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Runtime       : Node.js
   └─ Kenapa?    : JavaScript di server. Konsistensi bahasa dengan frontend (React).

2. Framework     : Express.js
   └─ Kenapa?    : Paling populer, ringan, banyak tutorial. Cocok untuk belajar REST API.

3. Database      : PostgreSQL
   └─ Kenapa?    : Relational DB, cocok untuk data terstruktur (kategori + entri log).
   └─ Alternatif : SQLite (lebih simple, file-based, bagus untuk belajar awal)

4. ORM           : Prisma
   └─ Kenapa?    : Autocompletion, schema visual, type-safe query, migrasi mudah.
   └─ Apa itu?   : ORM = perantara antara kode kamu dan database, jadi kamu nulis
                   kode JavaScript/TypeScript, bukan SQL mentah.

5. Auth          : JWT (JSON Web Token)
   └─ Kenapa?    : Stateless auth — token disimpan di client, server tidak perlu session.
   └─ Package    : jsonwebtoken + bcryptjs (untuk hash password)

6. Bahasa        : TypeScript (direkomendasikan) atau JavaScript biasa

7. Struktur file : RESTful API
   └─ Artinya    : API yang mengikuti konvensi HTTP Method + URL path

Ada 3 tabel utama:

┌─────────────────────────────────────────────────┐
│  Tabel: User                                    │
├─────────────┬──────────┬─────────────────────────┤
│ Field       │ Tipe     │ Keterangan              │

│ id          │ String   │ Primary key (UUID)      │
│ userId      │ String   │ Foreign key → User      │
│ name        │ String   │ Nama kategori           │

│  Tabel: Entry                                   │

  - 1 User → banyak Category
  - 1 User → banyak Entry
  - 1 Category → banyak Entry

  BAGIAN 4: SEMUA ENDPOINT API YANG HARUS DIBUAT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Format: [METHOD] /path → fungsi

── AUTH (tidak perlu token) ──────────────────────────────────

  POST   /api/auth/register
  └─ Input  : { name, email, password }
  └─ Proses : Hash password → simpan ke DB → kembalikan JWT token
  └─ Output : { token, user: { id, name, email } }

  POST   /api/auth/login
  └─ Input  : { email, password }
  └─ Proses : Cari user by email → bandingkan password hash → buat JWT
  └─ Output : { token, user: { id, name, email } }

── CATEGORIES (perlu token / harus login) ────────────────────

  GET    /api/categories
  └─ Fungsi  : Ambil semua kategori milik user yang login
  └─ Output  : [ { id, name, unit, color, icon }, ... ]

  POST   /api/categories
  └─ Input   : { name, unit, color, icon }
  └─ Fungsi  : Buat kategori baru untuk user yang login
  └─ Output  : Kategori yang baru dibuat

  PUT    /api/categories/:id
  └─ Input   : { name?, unit?, color?, icon? }
  └─ Fungsi  : Update kategori (hanya milik user sendiri)
  └─ Output  : Kategori yang sudah diupdate

  DELETE /api/categories/:id
  └─ Fungsi  : Hapus kategori (dan semua entri yang pakai kategori itu)
  └─ Output  : { message: "Deleted" }

── ENTRIES (perlu token / harus login) ───────────────────────

  GET    /api/entries
  └─ Query   : ?categoryId=...&from=YYYY-MM-DD&to=YYYY-MM-DD (opsional filter)
  └─ Fungsi  : Ambil semua log entry milik user (bisa difilter)
  └─ Output  : [ { id, categoryId, date, value, note }, ... ]

  POST   /api/entries
  └─ Input   : { categoryId, date, value, note? }
  └─ Fungsi  : Tambah log entry baru
  └─ Output  : Entry yang baru dibuat

  PUT    /api/entries/:id
  └─ Input   : { value?, note?, date? }
  └─ Fungsi  : Update entry (hanya milik user sendiri)
  └─ Output  : Entry yang sudah diupdate

  DELETE /api/entries/:id
  └─ Fungsi  : Hapus satu entry
  └─ Output  : { message: "Deleted" }

  BAGIAN 5: PENJELASAN TIAP FILE — FUNGSI DAN ISI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[1] prisma/schema.prisma
    ─────────────────────
    Fungsi : Mendefinisikan struktur database (model / tabel).
    Isi    : 3 model: User, Category, Entry beserta field dan relasinya.
    Cara   : Setelah ditulis, jalankan "npx prisma migrate dev" untuk
             membuat tabel di database secara otomatis.

[2] src/lib/prisma.ts
    ──────────────────
    Fungsi : Membuat 1 instance PrismaClient yang dipakai di seluruh app.
    Isi    : Export satu variabel "prisma" yang bisa diimpor di mana saja.
    Kenapa : Kalau kamu buat new PrismaClient() di tiap file, akan ada
             banyak koneksi database yang terbuang (memory leak).

[3] src/index.ts
    ─────────────
    Fungsi : Entry point — server dijalankan dari sini.
    Isi    :
      - Import express
      - Pasang middleware global: cors(), express.json()
      - Pasang semua routes: app.use('/api/auth', authRouter), dll
      - app.listen(PORT) — mulai mendengarkan request

[4] src/middleware/auth.ts
    ───────────────────────
    Fungsi : Middleware yang mengecek apakah request membawa JWT token yang valid.
    Cara kerja :
      1. Baca header "Authorization: Bearer <token>"
      2. Verifikasi token dengan JWT_SECRET
      3. Kalau valid → simpan data user ke req.user → lanjut ke route
      4. Kalau tidak valid → kirim respons 401 Unauthorized
    Dipakai di: semua route categories dan entries

[5] src/routes/auth.ts
    ───────────────────
    Fungsi : Menangani register dan login.
    Isi    :
      - POST /register : validasi input → hash password (bcrypt) → simpan user → buat JWT → return token
      - POST /login    : cari user → cek password → buat JWT → return token

[6] src/routes/categories.ts
    ─────────────────────────
    Fungsi : CRUD untuk kategori.
    Isi    :
      - GET    / → prisma.category.findMany({ where: { userId: req.user.id } })
      - POST   / → prisma.category.create(...)
      - PUT    /:id → cek ownership → prisma.category.update(...)
      - DELETE /:id → cek ownership → prisma.category.delete(...)
    Penting : Selalu filter by userId agar user A tidak bisa akses data user B!

[7] src/routes/entries.ts
    ───────────────────────
    Fungsi : CRUD untuk log entry.
    Isi    :
      - GET    / → ambil entry dengan filter opsional (tanggal, kategori)
      - POST   / → buat entry baru
      - PUT    /:id → update entry
      - DELETE /:id → hapus entry
    Penting : Sama — selalu filter by userId!

[8] .env
    ─────
    Fungsi : Menyimpan konfigurasi rahasia (jangan di-commit ke GitHub!).
    Isi    :
      DATABASE_URL="postgresql://user:password@localhost:5432/trackly"
      JWT_SECRET="string-random-panjang-untuk-signing-token"
      PORT=3000

  BAGIAN 7: KONSEP PENTING YANG HARUS DIPAHAMI SEBELUM MULAI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A. HTTP Methods
   ─────────────
   GET    → Ambil data (tidak mengubah apapun)
   POST   → Buat data baru
   PUT    → Update data yang sudah ada
   DELETE → Hapus data

B. Middleware
   ──────────
   Kode yang berjalan DI TENGAH antara request masuk dan response keluar.
   Contoh: cek token JWT sebelum route handler dieksekusi.
   app.use(middleware) → berlaku global
   router.get('/', middleware, handler) → berlaku hanya di route itu

C. JWT (JSON Web Token)
   ─────────────────────
   Token terenkripsi berisi data user (id, email).
   Dikirim client di setiap request: Header "Authorization: Bearer <token>"
   Server verifikasi token → kalau valid, tahu siapa yang request.
   Token punya expiry time (misal: 7d = 7 hari).

D. Password Hashing (bcrypt)
   ──────────────────────────
   Password TIDAK boleh disimpan plain text di database.
   bcrypt.hash(password, 10) → ubah password jadi string acak
   bcrypt.compare(input, hash) → cek apakah password cocok
   Angka 10 = "salt rounds" (makin besar makin aman, tapi makin lambat)

E. Environment Variables (.env)
   ──────────────────────────────
   Variabel konfigurasi yang berbeda-beda per environment (dev/production).
   Jangan hardcode DATABASE_URL atau JWT_SECRET langsung di kode!
   Gunakan: process.env.DATABASE_URL

F. CORS
   ─────
   Konfigurasi yang mengizinkan frontend (localhost:5173) untuk
   berkomunikasi dengan backend (localhost:3000).
   Tanpa CORS → browser akan block request dari frontend ke backend.
